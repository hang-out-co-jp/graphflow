# GraphFlow 業務フロー設計盤

ブラウザのGUIで業務フローを設計し、`.claude/workflows/` に dynamic workflow スクリプトを書き出します。

## やること

1. プラグインの `bin/` は **Bash ツールの** PATH に載っているので、あなたはそのまま起動できる。
   ⚠ ユーザー自身のターミナルには載っていない。「ターミナルで打ってください」と案内するときは、
   先に `~/bin` などへのシンボリックリンクを張る手順を添えること（README 参照）:

   ```bash
   graphflow
   ```

   引数なしで空の図面、`graphflow path/to/foo.graphflow.json` で既存の図面を開きます。
   `--port` で待受ポートを変えられます（既定 7391）。

2. 起動するとURLが出るので、**そのURLをユーザーに伝える**。ブラウザは自動で開きます。
   サーバーはフォアグラウンドで動き続けるため、**必ずバックグラウンドで起動する**こと。

3. ユーザーが「書き出し」まで進んだら、GUIの `.claude/workflows/ に保存` ボタンで
   スクリプトと設計JSONが書き込まれます。書き込み先は `graphflow` を起動した
   ディレクトリ配下の `.claude/workflows/` に限定されています。

4. 保存できたら、**AIを1体も呼ばずに空回しして確かめる**（課金は発生しません）:

   ```bash
   graphflow-dryrun .claude/workflows/<図面名>.js --pass
   graphflow-dryrun .claude/workflows/<図面名>.js --pass --null 3 --log
   ```

   2本目は「3体に1体が `null` を返す」状況を作ります。公式仕様で `agent()` は中断・
   回復不能なAPIエラーのとき `null` を返すので、**落ちても気づけるか**をここで見ます。
   `⚠` がひとつも出ずに完走したら、それは静かに欠けています。

   🔴 **図面に「1体が複数件返す」の並列があるときは、いきなり本番に行かないこと。**
   空回しは `--each` に渡した数でしか答えません。想定値のまま空回ししても、
   **自分が入れた数字が返ってくるだけ**で何も確かめていません。順番はこうです:

   ```
   ① 空回し                  課金0。最後まで走るか
   ② 1回だけ本当に走らせる   1体が実際に何件返すかを測る  ← ここを飛ばさない
   ③ 測った数で空回し直す    graphflow-dryrun ... --each <実測値>
   ④ 本番
   ```

5. 保存後、`/reload-plugins` は不要です。新しいセッションから `/<図面名>` で起動できます。
   同一セッションで使いたい場合はユーザーにその旨を伝えます。

## 設計を手伝うときの構え

ユーザーが「何を並列にすればいいか分からない」と言ったら、**偽のエッジテスト**を一緒に回します。

> その仕事は、本当に直前の仕事の結果を必要としますか？

必要としないなら、それは偽のエッジです。同じ段に置きます。
直列に並んでいるのは依存があるからではなく、人がその順番で書いたからであることが大半です。

点検（バリデーション）が出す指摘は、GUI側が全部日本語で説明します。
**指摘を回避するために設計を薄くしないこと。** 契約・検証者・アンカーが要求されるのは、
それが無いグラフは「同じ間違いをするAIを100体並べただけ」になるからです。

### 相談されやすい3点

- **並列を立てたのに材料が集まらない** → 既定は**1体1件**です。4本立てても4件にしかなりません。
  並列の部品の **1体が複数件返す** を入れ、**1体あたり何件くらい返る想定か** を決めます。
  この数は AI に渡す目標ではなく、見積り・空回し・上限判定の目盛りです。

- **検証者が的外れな指摘を返す** → 検証の **何を確かめるか** が段と合っていない可能性があります。
  事実／決めた基準どおり／読み物として／手元で再現できるか の4つで、渡す問いが丸ごと入れ替わります。

- **「直したか」を見る検証が機能しない** → 🔴 **検証者は「検証する相手」の出力しか読みません。**
  依存の線を引いても中身は渡りません（点検 `K-38`）。指摘リストや仕様は
  **判定の基準として渡すもの** の欄に入れます。検証する相手＝答案、判定の基準＝模範解答です。

- **繰り返しが積み上がらない（毎周おなじ結果）** → 点検 `K-41`。繰り返しの中の仕事が、
  繰り返しの**外**にある現物を直に読んでいると、その中身は毎周1周目のままです。
  現物は繰り返しの入口から順に渡します。

- 🔴 **「調べるだけ」の段が勝手に直してしまう** → 点検 `K-33`。部品の
  **この仕事はファイルを書き換えますか** に「書き換えない」と答えます。
  その段は `Edit`/`Write`/`NotebookEdit`/`Bash`/`PowerShell`/`Agent` を持たない担当で走ります
  （ブラウザ操作＝MCP と、読む・探すはそのまま使えます）。
  **指示文で「直さないでください」と書くだけでは止まりません**（下記）。
  ⚠ コマンドの実行が要る段は「書き換える」を選ばせてください。`Bash` があると書けてしまうので、
  半端に外すと「書けないことになっているのに書ける」状態になります。

## 実測で分かっている、いちばん危ない壊れ方

ひな形「UI操作の不備を潰す」を実際に走らせたときの記録です。

```
洗い出す（書かない宣言） … 1体が実装ファイルを 7回編集
テストを実施（書かない宣言）… 実装ファイルを 41回編集
落ちたものを直す（書いてよい）… 1文字も書かず「直すもの無し」
```

実施の担当がテストしながら自分で直し、自分が直したものをテストして「51件中0件が失敗」と報告。
次の段には直すものが残らず、検証者は「直すものが無いのは正しい」と合格を出しました。
**実際に行われた413行の変更を、誰も検証しないまま通りました。**

検証は正しく働いていました。**検証する相手が入れ替わっていた**だけです。
ユーザーが「テストする段」「調べる段」を置いたら、**ファイルを書き換えるかを必ず答えさせてください。**

## 覚えておく制約

- 🔴 **`graphflow:no-write`（書けない担当）が使えるのは、プラグインを入れた次のセッションからです。**
  入れた直後の同じセッションで走らせると `⚠ …見つかりませんでした` が出て、
  **書ける状態のまま進みます**（＝「書き換えない」と答えた段が書けてしまう）。
  ユーザーが入れたばかりなら、走らせる前にセッションを開き直すよう伝えてください。実測で踏んだ穴です。
- 実行中に人間の入力は挟めません。**承認が要るなら図面が2枚に割れます**（GUIが自動で割ります）。
- 同時実行は最大16エージェント、1回の実行全体で最大1000エージェント。
- dynamic workflows には Claude Code v2.1.154 以降が必要です。Pro プランでは `/config` の
  Dynamic workflows を有効にしてもらう必要があります。
- 生成されたスクリプトを手で直すと、次回の書き出しで上書きされます。**図面（.graphflow.json）側を直します。**

## GUIを使わない場合

ユーザーがターミナルから離れたくない場合は、GUIを開かずに同じ7点を対話で埋めても構いません。
ノード／契約／偽のエッジ／検証者／アンカー／人間ゲート／上限。
埋まったら、あなたが直接 dynamic workflow スクリプトを書いて `.claude/workflows/` に置きます。
